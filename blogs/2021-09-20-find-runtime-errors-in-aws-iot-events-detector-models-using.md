<p>Customers use <a href="https://aws.amazon.com/iot-events/">AWS IoT Events</a>&nbsp;detector models to describe equipment states and the events that affect these states. A detector model in AWS IoT Events contains expressions written in the <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-expressions.html">AWS IoT Events expression language</a>. An expression can have one of four primitive data types: integer, string, decimal, or Boolean. By checking your expressions for correct use of data types, you can be confident that your detector model will work as you expect. In this post, we describe the consequences of using wrong data types in your AWS IoT Events detector models. We show how the <a href="https://aws.amazon.com/blogs/iot/troubleshoot-aws-iot-events-detector-model/">troubleshooting feature of AWS IoT Events</a> detects these type errors before executing your detector model.</p> 
<p>AWS IoT Events is a fully managed service that makes it easy to detect and respond to events from IoT sensors and applications by creating a detector model. To learn more about detector models, see the&nbsp;<a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-getting-started.html">Getting Started with the AWS IoT Events Console</a>&nbsp;guide.</p> 
<h2>How type checking in AWS IoT Event expressions can help you</h2> 
<p>In this blog we will use the example of an industrial forklift. We will monitor it using an <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-detector-model.html">AWS IoT Events detector model</a>, introduce a runtime error, and then show how to troubleshoot it.</p> 
<p>When our example forklift picks up an item, it updates two attributes of an <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-detector-input.html">input in AWS IoT Events</a>. One of them is <code>weight</code>, the weight of the item being lifted by the forklift. The second attribute is <code>isWeightLb</code>, which indicates whether the weight is in pounds or kilograms. Our developer uses these attributes in two ways. First, the receipt of a new value for <code>isWeightLb</code> is used as a heartbeat, in other words, an indicator that the forklift is active. If a value is not received at least once every five minutes, the forklift’s status is changed to offline and a notification is sent.</p> 
<p>The monitoring of the forklift for a heartbeat is modeled using a detector model in AWS IoT Events shown in the following figure. The <strong>Offline</strong> state represents that the forklift has not sent a new value for <code>isWeightLb</code> in the last five minutes.</p>

<h3>Setting up an ‘Alert if too heavy’ event</h3> 
<p>Our developer also uses the preceding detector model to trigger a notification when the forklift lifts too heavy an item. Our developer notifies a SNS topic whenever the forklift lifts an item that is heavier than 4500 lbs. This event is detected via the <strong>Alert if too heavy</strong> event shown in the following figure.</p>

<h3>Setting up a ‘Publish to asset property’ event</h3> 
<p>Our developer makes one more addition to this detector model. They have already modeled the industrial forklift with an <a href="https://docs.aws.amazon.com/iot-sitewise/latest/userguide/industrial-asset-models.html">asset model</a> in <a href="https://aws.amazon.com/iot-sitewise/">AWS IoT SiteWise</a>. They wish to populate the <code>isWeightLb</code> asset property of their forklift assets in AWS IoT SiteWise using the <code>isWeightLb</code> input attribute to their AWS IoT Events detectors. Upon receiving a heartbeat, they make their detector model populate an <a href="https://docs.aws.amazon.com/iot-sitewise/latest/userguide/asset-properties.html">asset property</a> in a Forklift asset in AWS IoT SiteWise via the <strong>Publish to asset property</strong> <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-other-aws-services.html#iotevents-iotsitewise">AWS IoT SiteWise action</a> shown in the following figure.</p>

<h3>Introducing a runtime error</h3> 
<p>We will now introduce an error that is especially common when modeling complex systems. The <code>HeartBeat</code> input has two attributes <code>isWeightLb</code> (is the weight measured in pounds or kilograms?) and <code>weight</code> (the weight of the item lifted by the forklift). Our developer meant to pass the input attribute <code>isWeightLb</code> from their AWS IoT Events detector model to their asset property in AWS IoT SiteWise. But, they pass the <code>weight</code> attribute from the input to AWS IoT SiteWise as if the field is a Boolean.</p> 
<p>Every time this action is executed, AWS IoT Events will attempt to send the value in the <code>weight</code> attribute of the <code>HeartBeat</code> input as a Boolean value to the <code>forklifts/forklift1/isWeightLb</code> asset property in AWS IoT SiteWise.</p> 
<p>But, for the value to be correctly ingested into AWS IoT SiteWise, the value contained in the <code>weight</code> attribute of the <code>HeartBeat</code> input <em>must</em> be of Boolean type. If it is not, the action will fail to send the value contained in <code>weight</code> to the <code>forklifts/forklift1/isWeightLb</code> asset property in AWS IoT SiteWise. This failure will occur not just from this detector, but all detectors that contain this AWS IoT SiteWise action. Our developer may think this is happening because their detectors have stopped receiving a heartbeat message. Instead, the detectors are receiving the heartbeat message, but are unable to handle <code>weight</code> as a Boolean.</p> 
<p>To find the root cause of this issue, our developer will:</p> 
<ol> 
 <li><a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/best-practices.html#best-practices-cw-logs">Enable logging in AWS IoT Events</a> and check the detector’s logs in <a href="https://aws.amazon.com/cloudwatch/">Amazon CloudWatch</a> for incoming heartbeat messages.</li> 
 <li>Verify that the declared data type of the <code>forklifts/forklift1/isWeightLb</code> asset property in AWS IoT SiteWise is Boolean.</li> 
 <li>Verify that the <code>isWeightLb</code> attribute in the <code>HeartBeat</code> input in AWS IoT Events contains a Boolean value at runtime.</li> 
</ol> 
<p>However, none of these steps will reveal to our developer that their detector model mistakenly sends the <code>weight</code> input attribute as a Boolean value to AWS IoT SiteWise, instead of the <code>isWeightLb</code> input attribute.</p> 
<p>To reduce such debugging pain, the troubleshooting feature of AWS IoT Events searches for inconsistencies between the expected and actual data types of input attributes in your detector model. For example, in this situation, the troubleshooting feature warns our developer that the inferred data type, integer, for <code>$input.HeartBeat.weight</code> does not match the expected data type, Boolean, in the AWS IoT SiteWise action.</p> 
<h2>Troubleshooting data type errors</h2> 
<p>The <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-expressions.html">AWS IoT Events expression language</a> allows you to have input attributes and variables which need to have one of four primitive data types: integer, decimal, string, and Boolean. You do not declare data types for your input attributes or variables used in your detector model. The <a href="https://aws.amazon.com/blogs/iot/troubleshoot-aws-iot-events-detector-model/">troubleshooting feature of AWS IoT Events</a> can infer data types for them by analyzing their use within expressions in your detector model.</p> 
<p>For example, consider that the <strong>Alert if too heavy</strong> event in the preceding detector model has the following condition, <code>$input.HeartBeat.weight &gt; 4500</code>. This expression compares an input attribute, <code>weight</code>, against an integer literal, <code>4500</code>. Since the input attribute weight is being compared with a value of integer type, it is meant for storing a value of integer type and therefore must be of integer type.</p> 
<p>AWS IoT Events infers data types for the input attributes and variables used in your detector model by leveraging the type rules of the <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-expressions.html">AWS IoT Events expression language</a>. These rules dictate the types of the operands that an operator or function in the language is allowed to operate over. For example, the type rule for the <code>&gt;</code> operator in the AWS IoT Events expression language is:</p> 
<blockquote>
 <p>if one operand of <code>&gt;</code> is of type integer, the other operand must be of type integer</p>
</blockquote> 
<p>When analyzing your detector model, the troubleshooting feature of AWS IoT Events matches each expression against the type rule that applies to it. It infers data types for operands of operators and arguments of functions. Once a data type is inferred for an input attribute or variable, the troubleshooting feature uses this information to check your expressions in other actions for type correctness.</p> 
<h3>Example: Catching type errors with IotSitewiseActions</h3> 
<p>Consider the AWS IoT SiteWise action shown in the preceding figure. When you choose <strong>Run Analysis</strong> in the AWS IoT Events console shown in the following figure, the troubleshooting feature of AWS IoT Events will analyze all expressions in the detector model, including the comparison expression <code>$input.HeartBeat.weight &gt; 4500</code>, to infer that <code>$input.HeartBeat.weight</code> must be of integer type.</p> 
<p><img alt="Screenshot from AWS IoT Events console highlighting the &quot;Run Analysis&quot; button" class="size-large wp-image-6129 aligncenter" height="64" src="https://d2908q01vomqb2.cloudfront.net/f6e1126cedebf23e1463aee73f9df08783640400/2021/09/17/Run-Analysis-screenshot-with-shadow-1024x64.png" width="1024" /></p> 
<p>Next, AWS IoT Events will examine the expressions in the AWS IoT SiteWise action of the detector model. It will find that the expression, <code>$input.HeartBeat.weight</code>, is to be sent as a Boolean value to the asset property <code>forklifts/forklift1/isWeightlb</code> in AWS IoT SiteWise. But, since the inferred data type, integer, for the expression, <code>$input.HeartBeat.weight</code>, does not match the data type Boolean declared in the AWS IoT SiteWise action, AWS IoT Events will report the warning shown in the following figure.</p> 
<p>The warning message states, “<strong>The expression in the IotSitewiseAction field [$input.HeartBeat.weight] is defined as type Boolean and inferred as type Integer. The defined type and the inferred type must be the same.</strong>” This warning indicates that AWS IoT Events has inferred the expression <code>$input.HeartBeat.weight</code> to be of type integer. But, your AWS IoT SiteWise action assumes that the runtime value evaluated from this expression will be of Boolean type. The <strong>Location</strong> field in the warning tells us that the warning is reported in an AWS IoT SiteWise action in the <strong>Normal</strong> state’s <strong>onEnter</strong> event list in an event named <strong>Publish to asset property</strong>.</p> 
<p><img alt="Warning reported by AWS IoT Events on the IotSitewiseAction in the ForkliftMonitoring detector model" class="size-large wp-image-6130 aligncenter" height="962" src="https://d2908q01vomqb2.cloudfront.net/f6e1126cedebf23e1463aee73f9df08783640400/2021/09/17/Full-DM-analysis-Sitewise-action-warning-screenshot-with-shadow-1024x962.png" width="1024" /></p> 
<h3>Example: Catching type errors with custom payload expressions</h3> 
<p>Similar to how your expression in your AWS IoT SiteWise action needs to have a specific declared data type, AWS IoT Events also expects your <a href="https://docs.aws.amazon.com/iotevents/latest/apireference/API_Payload.html">custom payload expressions</a> to be of string type. For example, consider the action shown in the preceding figure, that showed the <strong>Alert if too heavy</strong> event, in which you use the custom payload expression <code>"Last weight exceeded 4500, reported: " + $input.HeartBeat.weight</code>.</p> 
<p>Since <code>$input.HeartBeat.weight</code> is used as an integer in the event condition <code>$input.HeartBeat.weight &gt; 4500</code> of the <strong>Alert if too heavy</strong> event, it cannot be used as part of a string payload directly. The troubleshooting feature reports this issue with the following warning:</p> 
<p><img alt="Screenshot from AWS IoT Events console showing the warning for the custom payload action" class="size-large wp-image-6131 aligncenter" height="115" src="https://d2908q01vomqb2.cloudfront.net/f6e1126cedebf23e1463aee73f9df08783640400/2021/09/17/custom-payload-warning-screenshot-with-shadow-1024x115.png" width="1024" /></p> 
<h2>Conclusion</h2> 
<p>Customers have told us that creating AWS IoT Events detector models, which are a part of a complex system, can be challenging. In this post, we discussed the <a href="https://aws.amazon.com/blogs/iot/troubleshoot-aws-iot-events-detector-model/">troubleshooting feature of AWS IoT Events</a>. This feature simplifies the debugging experience for customers by finding type-correctness issues with the detector model without sending any data to it and without even publishing it.</p> 
<p>You can learn more about the type-based warnings and errors reported by this feature by reading our <a href="https://docs.aws.amazon.com/iotevents/latest/developerguide/iotevents-analyze-api.html">documentation</a>. You can <a href="https://aws.amazon.com/blogs/iot/troubleshoot-aws-iot-events-detector-model/">use the troubleshooting feature</a> to check if the inferred data types reported by it match your expectations. Now that you can find type-correctness issues with your detector model without publishing it, choose <strong>Run Analysis</strong> when editing your detector model in the <a href="https://console.aws.amazon.com/iotevents/">AWS IoT Events console</a> to be even more confident with using your detector model.</p>
